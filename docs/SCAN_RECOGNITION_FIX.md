# Единый разбор сканов заявок — 24.09.2026

## Подтверждённая проблема

В двух приложенных пользователем выгрузках одной двухстраничной заявки локальный режим содержал 8 слушателей и программу первой помощи, а Vision — 5 слушателей без программы. ФИО и идентификаторы в ответе Vision отличались от оригинала. Значение начала обучения, подтверждённое пользователем: 24.09.2026.

Причины в коде:

- В `doc_reader.parse_incoming_application` успешный ответ Vision возвращался до локального OCR без сверки полноты и полей. Локальный и ИИ-режимы использовали разные цепочки обработки.
- В Vision уходили изображения PDF без отдельного определения ориентации каждой страницы. У исходного файла первая страница требует дополнительного поворота на 90° против часовой стрелки; вторая уже отображается горизонтально с учётом поворота PDF.
- `ai_vision._normalize_vision_response` принимал `programs`, но игнорировал альтернативное поле `program` и `fio_nom`.
- Локальный `parse_scanned_table_text` выбирал начало после приглашения «Просим обучить» до проверки реального заголовка таблицы. Порядок блоков OCR мог поместить туда адресата и подменить первого слушателя именем руководителя.
- При неизвестной программе локальный парсер подставлял первую помощь; символ `%` в СНИЛС заменялся на `4`. Эти предположения удалены.

## Реализованное поведение

`scan_recognition.py` формирует общий локальный результат для сканов PDF, в том числе смешанных PDF с текстовыми и сканированными страницами, и распознанных заявок в изображениях/многостраничном TIFF.

1. PDF отображается в 300 dpi с учётом метаданных поворота; для изображений учитывается EXIF.
2. Для каждой страницы отдельно определяется ориентация средствами Tesseract OSD. При недостаточной уверенности или недоступности OSD оцениваются четыре варианта OCR.
3. Все страницы разбираются совместно, включая продолжение таблицы на следующем листе.
4. Включение Vision добавляет проверку нормализованных страниц. Ответ ИИ не заменяет локальный список и его значения.
5. Сопоставление допускается только по совпадению полного ФИО или СНИЛС и только при однозначном результате. Форматирование СНИЛС не считается изменением цифр.
6. Расхождения и неподтверждённые локальные строки видны в аудите; соответствующие ячейки выделяются. Дополнительные строки ИИ сохраняются в `audit.ai_candidates` и показываются для ручной сверки. Они не включаются в основную заявку автоматически.
7. На этом пути исходное распознанное ФИО сохраняется; предполагаемая лингвистическая правка требует сверки. Если дательный падеж есть в источнике, он также сохраняется. При отсутствии дательного падежа действует существующее образование формы.
8. Ошибка API или обрезанный ответ не уничтожает локальный результат. Пользователь получает предупреждение и признак необходимости проверки.
9. Даты и программа проходят единый существующий каталог и календарь; явно заданные ручные параметры имеют приоритет.

UI теперь описывает дополнительную сверку ИИ для сканов заявок. Содержимое предупреждений и дополнительных строк выводится как текст.

## Проверки

`python3 tools/run_quality_tests.py`: 76 тестов, 74 успешно, 2 ранее существовавших пропуска, ошибок нет. Отчёт: `docs/validation.json`.

Добавлено 14 синтетических тестов: пропуски и изменения ИИ, дубликаты, неподтверждённые строки, ошибка API, обрезанный ответ, варианты полей JSON, ориентация/резервный выбор, обработка всех страниц и очистка временных файлов, смешанный PDF, TIFF, отсутствие выдуманной программы, адресат перед таблицей, сохранение ручной даты и равенство содержимого DOCX/XLSX при разногласиях ИИ.

Реальная заявка проверена локально при поворотах 0/90/180/270°: одинаковые 8 слушателей. ФИО, даты рождения и СНИЛС всех восьми строк дополнительно сверены с визуальным оригиналом. Программа — «Программа обучения по оказанию первой помощи пострадавшим», 16 часов, 2 рабочих дня. При ручной дате 24.09.2026 с ролью `start` результат: **24.09.2026–25.09.2026**.

Вместо живого запроса в OpenAI воспроизведён ошибочный ответ из приложенного DOCX: итоговые значения остались идентичны локальному режиму, неподтверждённые строки выведены на проверку. Отчёт без персональных данных: `docs/scan-parity-validation.json`.

## Границы и эксплуатация

- Это не доказательство 100% точности на любых сканах. Нечитаемые строки и сомнительные символы требуют человека. Совпадение двух движков тоже не доказывает правильность.
- Исправление общего конвейера относится к сканам заявок. Существующие специализированные ветки отдельных паспортов/СНИЛС, текстовых сообщений и семантического разбора DOCX не унифицированы этим изменением.
- При неуверенном OSD четыре OCR-прохода увеличивают время обработки. При отсутствующем Tesseract полноценный локальный результат невозможен; ИИ не выдаётся за надёжную замену.
- Для уверенного определения ориентации на сервере нужен Tesseract с русским языком и `osd`. Наличие языков проверяется `tesseract --list-langs`. При отсутствии `osd` работает резервный выбор; он слабее на страницах с малым количеством текста.
- Живая работа OpenAI и поведение конкретной серверной сборки Tesseract в этой проверке не подтверждены. Запросы с персональными данными наружу не отправлялись.
- Для одной введённой даты в интерфейсе необходимо выбрать **«Начало обучения»**. В режиме «Уточнить значение даты» срок намеренно не угадывается.
- Исходные PDF/DOCX и извлечённые персональные данные не входят в репозиторий или тестовые фикстуры. Для воспроизведения реального случая нужны пользовательские файлы.
- Изменения подготовлены локально. Production не изменялся. До публикации этого исправления обычный `git pull` на сервере его не установит.

# Ручные параметры и подтверждение программ

Изменение от 28.09.2026. Сохранены текущие стили, цвета и типографика приложения. Основная форма теперь открывает native dialog справа; на узких экранах панель занимает всю ширину. Escape закрывает панель, фокус возвращается к кнопке открытия.

## Поведение

После анализа backend возвращает `program_questions`: исходное спорное название, число соответствующих строк, варианты каталога и подтверждённый ID. Пользователь выбирает один вариант и подтверждает замену. Она применяется только к этому названию, а не ко всей заявке. Выбор из полного каталога также сохраняется в карточке. Можно изменить подтверждённый выбор или сбросить параметры.

Часы берутся из каталога; при наличии вариантов пользователь выбирает часы, при отсутствии длительности указывает их явно. Краткие подписи вариантов высоты используются только в UI. Полные названия сохраняются в расчёте и выгрузках. Программы «демо» и исключённые не предлагаются.

«Задать программы для всей заявки» вынесено в отдельный раскрывающийся раздел с явным предупреждением об области действия. Должность по умолчанию заполняет только пустые значения. Сроки представлены выбором начала, окончания или интервала. Пока программа/часы/сроки не определены, UI не запускает скачивание и предлагает открыть параметры. Это UX-ограничение, не механизм авторизации скачиваний.

## Поиск

Ведущий номер списка вида `18 –` игнорируется при сопоставлении полного названия; содержательные числа внутри названия (группа, разряд и т. п.) сохраняются. Неоднозначные совпадения остаются на подтверждение.

Для неоднозначных формулировок используется тематический фильтр (высота, ОЗП, электроустановки, земляные работы, первая помощь, СИЗ), затем текстовое ранжирование внутри направления. Это подбор по правилам и словарю, не отдельный LLM или embeddings. При отсутствии тематического совпадения остаются текстовые предложения; пользователь подтверждает их сам. Расширение словаря направлений — отдельное развитие.

## Пересчёт

`POST /api/process` принимает `program_replacements` — JSON-сопоставление исходных названий с ID действующих программ каталога. Недопустимые ID отклоняются кодом 422.

Первичная обработка сохраняет исходные распознанные записи в памяти процесса и возвращает случайный `recognition_token`. Повторный запрос с токеном пересчитывает заявку без повторного OCR/вызова Vision. Клиент не передаёт серверу произвольный список распознанных слушателей. В выгрузочных данных `recognition` сохраняются исходная программа, выбранный ID и `replaced_from`.

Сессии рассчитаны на один процесс приложения: максимум 100, срок 30 минут; устаревшие записи удаляются при следующем запросе обработки. Перезапуск процесса или истёкший токен требуют нового анализа (HTTP 410). Для нескольких workers потребуется общее хранилище. Изменение файлов/исходного текста в UI требует нового анализа, чтобы не применять старый снимок к другой заявке.
